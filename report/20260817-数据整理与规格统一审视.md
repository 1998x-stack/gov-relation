## 2. 已修复：SQLite 发布缺陷（真实 bug，均通过测试）

### 2.1 scripts/govdb.py — build 后 WAL 遗留使只读 audit 失败
- 现象：`govdb.py audit --database data/platform/gov_relation.db` 报 `sqlite3.OperationalError: unable to open database file`（只读 mode=ro URI 打开 WAL 库因缺少配套 -wal/-shm 失败），并在 data/platform/ 遗留 .building-wal/-shm 残留。
- 修复：`os.replace` 发布前对目标库执行 `wal_checkpoint(TRUNCATE)` + `journal_mode=DELETE` 并清理 sidecar，产物自包含、只读可开。
- 验证：audit / release-check 均通过，data/platform/ 只剩一个干净 db。

### 2.2 gov_relation/runner.py - v3 构建发布前未固化 WAL
- `_run_v3_build` 以 WAL 写临时库后 `os.replace` 发布，只读消费者（region_factory.generate_person_profiles）失败。
- 修复：`GEXFFactory().write` 后 close 前执行 checkpoint+DELETE 固化。
- 结果：`tests/test_factory/test_region_factory.py` 失败转通过，全量失败数 7 -> 6。

> 二者同为 SQLite WAL 只读打开陷阱在流水线两处体现，一并修复后"统一规格"中的只读契约得证。
